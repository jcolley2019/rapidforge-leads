## (a) State of the system

RapidForge is a real, working v1 that is further along than its live data shows. The code at `f286648` implements all 13 agents from the PRD roster except the Haiku Filter edge-pass and the Keyword Parser (a stub), with a clean deterministic-before-AI split: every score is pure math in `packages/shared/src/scoring.ts`, every LLM call goes through one seam (`apps/worker/src/lib/ai.ts`) with Zod parsing, pure guardrails, one re-run, and a deterministic template fallback, so a job never stalls on the model. The live Supabase project, however, has only ever run the Sprint 3 pipeline in **template mode**: all 616 `agent_runs` rows have `model_used = null`, 31 of 67 audited leads carry the guardrail note "AI Core wrapper is not wired yet", no audit has `v15_agents` (Design/Reputation/SEO), screenshots, an Analyst verdict, a Builder Brief, or a Sales Summary, and the newest search (hair salons, 2026-07-06) is frozen in `auditing` with 28 jobs stuck in `running` because the worker was killed and nothing reclaims stale claims. The live workspace also mixes 25 fixture businesses (`fx-*` place ids, 125 audits) with 106 real Google rows. The lead-quality problem is structural, not cosmetic: Sellability gives 60 of its 100 points to signals that have nothing to do with the website (reviews, rating, phone, chain, operational), so every operational independent with ≥20 reviews lands at ≥60 regardless of how good its site is, which is exactly the Analyst auto-run threshold; chains only lose 10 points; bot-blocked (403/503) sites are treated as live or "broken — urgent"; and the top of the ranked list is a mix of genuine Wix/GoDaddy prospects, 1-review no-website businesses, 4,000–8,700-review regional firms that already pay an agency, and Ulta Beauty at sellability 96. For the downstream demo-site generator, the Builder Brief is markdown-only today and the Places field masks never fetch hours, photos, or reviews, so about half of the requested structured-brief fields have no data source yet. The cold-clone story is the single most urgent hygiene item: `apps/worker/package.json` depends on `@rapidforge/ai-core` via an absolute path into Joey's OneDrive, so on any other machine `npm install` silently rewrites the lockfile, `tsc` fails, the worker cannot start, and 11 of 20 worker test files cannot load. **Test baseline on this clone: 201 tests pass, 0 fail, 11 worker suites unloadable** (shared 61/61, web 49/49, worker 91/91 across the 9 suites that load; `src/http.test.ts`, `src/orchestrator.test.ts`, `src/lib/ai.test.ts` and all 8 AI-agent suites fail at import with `Failed to load url @rapidforge/ai-core`). Typecheck: shared ✔, web ✔, worker ✘ (`TS2307` on the same import).

## (b) Agent map as implemented

Orchestration: `POST /api/searches` (`apps/worker/src/http.ts:128`) → `searches` row + `jobs(scout)` → `queue.ts` 2s poller claims via `SupabaseStore.claimNextQueuedJob` (`store/supabase.ts:195`) → `orchestrator.ts:handleJob`. Scout fans out one `audit_business` job per business (`orchestrator.ts:113`). Per business: Filter → (if live real site) shared fetches (homepage, PSI mobile + desktop, screenshots, sitemap/robots probes; `orchestrator.ts:228-236`) → seven agents in `Promise.all` → Scorer → `lead.scored` → Analyst auto-run when sellability ≥ 60 (`orchestrator.ts:336`). Builder Brief and Sales Summary are on-demand HTTP routes wrapped by `agents/on-demand.ts`. Every agent run writes `agent_runs` and broadcasts Realtime events via `withAgentRun` (`orchestrator.ts:372`).

No JSON contract, no Zod schema for a brief, no field the generator could rely on without parsing prose.

**Smallest change that adds the structured brief (not implemented here):**

1. **Migration 0007** — `alter table businesses add column places_details jsonb;` and `alter table audits add column design_brief jsonb;` (append-only, Joey pastes).
2. **Scout** — add `regularOpeningHours, photos, reviews, editorialSummary, types, priceLevel` to `DETAILS_FIELD_MASK` and call `getDetails` for every business that passes Filter (move the call from Scout into Filter's `pending_audit`/`hot_lead` branches so skips never pay for it); persist the raw record to `businesses.places_details`. Photo references become worker-proxied URLs (`GET /api/places/photo/:ref`) or are copied into the public bucket.
3. **Scorer** — include `conversion` (`cta_candidates`, `booking_url`, `visible_phone`) and `presence` (`social_links`) in `score_breakdown.v15_agents` (one object spread at `scorer.ts:171-175`), so every money agent and the brief can read them from the audit row.
4. **`packages/shared/src/design-brief.ts`** — a Zod `DesignBriefSchema` with exactly the requested fields (`business_name, vertical, tone_descriptors[], services[], review_quotes[≤5], photo_urls[], hours, phone, address, primary_cta{label,kind,href}, current_site_problem`), exported from `index.ts`.
5. **`apps/worker/src/agents/design-brief.ts`** — a deterministic assembler `buildDesignBrief(business, audit)` over `money-facts` + `places_details` (name, vertical, phone, address, hours, photos, best-5 reviews by rating then length, primary CTA = `booking_url` ▸ `tel:` ▸ first `cta_candidates[0]`, problem line = `analyst_output.one_line_verdict` ▸ `issues[0].label`), plus **one** Haiku 4.5 strict-JSON call for the two judgment fields (`tone_descriptors`, `services`) from the homepage excerpt + review text, with a template fallback (category→tone map, H1s→services). Guardrail: every quote must appear verbatim in `places_details.reviews`.
6. **Route** — `POST /api/businesses/:id/design-brief` via `runOnDemandAgent`, persisting to `audits.design_brief`; also run it inside `runBuilderBrief` so the markdown brief embeds the same JSON in a fenced block the generator can parse.

That is one migration, ~3 small edits, one new ~150-line agent, one route, and ~2¢ of Haiku per lead.
